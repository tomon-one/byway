# Как устроен byway

Документ для тех, кто чинит или дописывает byway либо выясняет, почему трафик
идёт не туда: путь пакета, правила перехвата, служба, периодические задачи и
файлы — с именами функций, опций UCI, портов и путей, как в коде.

Числа ниже — поставочные умолчания из `/etc/config/byway`, все настраиваются.
Где значение задаёт код, а не UCI, это сказано.

## Из чего состоит

| часть | роль |
|---|---|
| `/usr/local/bin/byway` | POSIX-скрипт (busybox ash): собирает конфиг Xray-core, ставит и снимает правила перехвата, проверяет состояние, обновляется |
| `/etc/init.d/byway` | служба procd: запускает Xray-core и зовёт `byway plumb on/off` |
| Xray-core | DNS-вход с подставными адресами, вход tproxy, маршрутизация, исходящие |
| таблица nft `inet byway` | перехват трафика доверенных мостов |
| `ip rule` + таблица маршрутизации 100 | доставка помеченных пакетов локальному сокету |
| dnsmasq | пересылает все запросы на DNS-вход Xray-core |
| cron | `byway watch` каждые 5 минут, `byway stat` раз в час, `byway pulse` раз в минуту |

«Правила перехвата» здесь — всё, что ставит `byway plumb on`: таблица nft, `ip
rule`, маршрут в таблице 100 и перенаправление dnsmasq.

## Путь пакета

```
устройство в br-lan
  │ DNS-запрос
  ▼
dnsmasq (server=127.0.0.42, noresolv=1)
  ▼
Xray-core: вход dns-in 127.0.0.42:53 → исходящее dns-out → встроенный DNS
  ├─ имя из списка → адрес из пула 198.18.0.0/15 (fakedns)
  └─ прочее        → dns_upstream (DoH), настоящий адрес
  │
  │ соединение на 198.18.x.x:443
  ▼
nft: table inet byway, chain prerouting (priority mangle)
  1. iifname не из byway.main.interface  → return
  2. ip daddr @privnets                   → return
  3. socket transparent 1                 → метка, accept
  4. ip daddr @fakeip / @subnets          → tproxy на :1602, метка 0x100000
  ▼
ip rule fwmark 0x100000/0x100000 lookup 100
table 100: local default dev lo           → доставка локальному сокету
  ▼
Xray-core: вход tproxy-in 0.0.0.0:1602, sniffing fakedns/http/tls/quic
  ▼
routing → proxy | route-ИМЯ | direct | block
```

### DNS и подставные адреса

dnsmasq пересылает всё на `dns_listen` (127.0.0.42). Там слушает
`dokodemo-door` с тегом `dns-in`; первое правило маршрутизации отдаёт его
исходящему `dns-out`, а тот — встроенному DNS. Серверы встроенного DNS:

- `fakedns` — для имён объединённого списка (свой `domains.lst`, готовые
  списки `list preset`, списки направлений) и для `full:example.com`;
- `dns_upstream`, затем `dns_upstream2` (`none` отключает) — для всего прочего;
- `dns_bootstrap` — только чтобы разрешить имена самих `dns_upstream*`, если
  они заданы именем. Резолвер задан именем, а `dns_bootstrap` пуст — `byway
  gen` предупреждает и берёт вместо них `https://8.8.8.8/dns-query` и
  `https://1.1.1.1/dns-query`.

На имя из списка fakedns отвечает локально, адресом из `fakeip_pool`. Наружу
за ним не ходит никто: настоящий адрес узнаёт сервер VPN, когда открывает
соединение.

`fakedns` стоит в `servers` последним и без `skipFallback`, то есть служит
запасным и для прочих имён: если оба `dns_upstream*` ответили пусто или не
ответили, имя не из списка тоже получает адрес из пула. Второй резолвер
спасает от молчания первого, но не от пустого ответа.

Таблица «адрес ↔ имя» живёт в памяти Xray-core, `poolSize` равен числу адресов
пула минус два (`pool_size`). Если имён больше, `byway gen` предупреждает:
вытесненный адрес достаётся другому имени, и устройство с прежним ответом в
кэше уйдёт к чужому хосту.

Перезапуск движка стирает таблицу, поэтому кэш dnsmasq надо сбросить. При
старте службы это делает `plumb on` через `dns_up`: HUP, если dnsmasq уже
смотрит на DNS-вход, иначе перезапуск dnsmasq. Если движок поднял сам procd
(`respawn`), кэш сбросит ближайший `byway watch`, заметив новый PID, — с
опозданием до 5 минут. До того dnsmasq отдаёт адреса, которых новый движок не
знает. Соединение на неизвестный движку адрес пула, у которого sniffing не
достал имя, попадает в правило `block`.

### Перехват в nft

Таблицу целиком печатает `byway nft` (функция `nft_ruleset`), ничего не
применяя. Наборы: `fakeip` (пул), `privnets` (`0/8`, `10/8`, `127/8`,
`169.254/16`, `172.16/12`, `192.168/16`, `100.64/10`, `224/4`, `240/4`),
`subnets` (объединённые подсети). Пул в `privnets` не входит, поэтому отсечка
частного стоит до правил tproxy и ничего нужного не съедает.

Порядок в `prerouting` важен. Перехватывается только то, что пришло с мостов
из `list interface`. Отсечка `privnets` стоит раньше короткого замыкания
`socket transparent`: иначе пакет, адресованный самому роутеру на порт tproxy,
получил бы метку, правило firewall приняло бы его по метке, и гостевая зона с
`input REJECT` перестала бы держать гостя. Метка ставится через `or`: чужие
биты сохраняются, `ip rule` сверяет по маске.

Цепочка `input` (priority `filter - 10`): `iif lo return`, правило отказа
QUIC, затем `drop` для tcp/udp на `tproxy_port` и для tcp на `redirect_port`
(при включённом IPv6 вход `redir-in` слушает `::`, то есть все интерфейсы).
Эти два правила закрывают прямые обращения к входам из сети; заворот трафика
роутера приходит через `lo` и до них не доходит. Перехваченный трафик они не
задевают: tproxy не переписывает адрес и порт назначения, такой пакет приходит
в `input` с исходным портом.

Отсюда же два следствия. Вход `tproxy-in` слушает `0.0.0.0`, а не петлю —
пакет доходит до сокета с адресом `198.18.x.x`. И нужно правило
`firewall.bywaytproxy` (src `*`, proto `all`, `mark M/M`, `ACCEPT`), которое
создаёт `install.sh`: без него зона с `input REJECT` отбрасывает
перехваченное. `byway plumb on` до укладки своей таблицы заводит правило
заново, если его нет (`uci commit firewall` и перезагрузка firewall), и
переписывает при смене `mark`. `byway doctor` при отсутствии правила
предупреждает.

Набор применяется одной транзакцией и начинается с `table inet byway` +
`delete table inet byway`. `nft -f` доливает в существующую таблицу, а не
заменяет её; без прелюдии сужение пула давало бы «interval overlaps» на
правильном наборе. Перед укладкой текст проверяется `nft -c -f -`.

### Маршрут по метке

`route_up` добавляет `ip rule add fwmark M/M lookup 100` и `ip route add local
default dev lo table 100`. Без них ядро переслало бы помеченный пакет дальше,
и сокет tproxy его не увидел бы. Номер таблицы — константа `RT_TABLE=100` в
коде: busybox `ip` не принимает номер больше 255. Чужие маршруты в таблице 100
byway не трогает и говорит о них. `route_down` удаляет маршрут, только если
его создал byway (отметка `/tmp/byway-route-mine`).

### Внутри Xray-core

`tproxy-in` — `dokodemo-door` с `followRedirect` и `sockopt.tproxy`. Sniffing
с `destOverride` `fakedns`, `http`, `tls`, `quic` и `routeOnly: false`:
назначение заменяется восстановленным именем, дальше маршрутизация работает с
ним. Правила, первое совпавшее выигрывает, `domainStrategy: IPIfNonMatch`:

| # | правило | куда |
|---|---|---|
| 1 | `inboundTag: dns-in` | `dns-out` |
| 2 | при `dns_route tunnel`: запросы встроенного DNS | `proxy` |
| 3 | направления: `/etc/byway/routes/ИМЯ.lst` | `route-ИМЯ` |
| 4 | `lists`: домены списка и `full:example.com` | `proxy` |
| 5 | `lists`: подсети списка | `proxy` |
| 4′ | `all` + `ru_direct 1`: `domain:ru`, `domain:su`, `domain:xn--p1ai` | `direct` |
| 5′ | `all`: адреса серверов из ключей | `direct` |
| 6 | частное, служебное и сам пул | `block` |
| 7 | всё прочее, `tcp,udp` | `direct` в `lists`, `proxy` в `all` |

`block` перед последним правилом обязателен. Без него `tproxy-in` был бы
открытым форвардером: гость открывает соединение на адрес пула, пишет в первом
пакете `Host: 192.168.1.1`, sniffing подменяет назначение, и наружу идёт сам
роутер — мимо цепочки `forward`, где гостей режет firewall. Пул в том же
правиле закрывает петлю «вход сам на себя».

Правило 2 уводит в туннель и запросы, которыми движок разрешает имена серверов
из ключей, а без этих адресов туннель не поднять. Поэтому при `dns_route
tunnel` `byway gen` разрешает имена серверов сам — пин из `/etc/hosts`, затем
через 8.8.8.8, затем 1.1.1.1, затем местный резолвер, затем берёт адрес из
прежнего `config.json` — и кладёт их в `dns.hosts`. Сменил сервер адрес —
раз в час это замечает `byway watch`, вручную — `/etc/init.d/byway reload`.

`example.com` (константа `PROBE_DOMAIN`) завёрнут в туннель всегда: по нему
`byway health` проверяет цепочку целиком, что бы ни лежало в списках.

При `conn_mode urltest` исходящих несколько (`proxy-0`, `proxy-1`, …), и
правила ведут в балансировщик `auto` (`leastPing`). `observatory` замеряет
ключи запросом к `https://www.google.com/generate_204` раз в `probe_interval`:
`3m` — умолчание в коде, в поставочном конфиге этой опции нет. Каждый ключ
сперва разбирается и собирается в подоболочке (`parse_node` и `build_stream`):
отказ на любом из шагов — `ключ пропущен: ПРИЧИНА`, ключ в балансировщик не
идёт. Ключ направления проверяется так же и при отказе пропускается вместе с
направлением. Не годится ни один ключ автовыбора — сборка отказывает.

### Режимы lists и all

`list_mode lists`: в туннель идут пул и подсети списка, остальное `direct`.

`list_mode all`: nft перехватывает всё с перечисленных мостов, что не попало в
`privnets`. Списки в маршрутизации не участвуют, последнее правило ведёт в
`proxy`. Исключения:

- `ru_direct 1` пускает `.ru`, `.su` и `.рф` мимо туннеля. `.рф` записан
  пуникодом `xn--p1ai` — в DNS и SNI идёт он. Имя берётся из sniffing.
- Адреса серверов всех ключей (`VPN_HOSTS`, включая серверы направлений) идут
  `direct`. Иначе петля: чтобы открыть соединение к серверу, движок разрешает
  его имя, и этот запрос по общему правилу уходит в ещё не поднятый туннель.

Для ключа в виде готового JSON (`conn_mode outbound`) адрес сервера byway не
знает и не исключит; `byway gen` предупреждает. Адрес сервера не должен
попасть в списки ни в каком режиме.

### Зачем сервису и домен, и подсеть

Маршрут решает DNS. Устройство, узнавшее адрес не у роутера (DoH в браузере,
«Частный DNS» Android, свой резолвер), получает настоящий адрес, и пул его не
касается. Исключение — Firefox, который включил DoH сам: его выключает
канарейка `use-application-dns.net` (см. «dnsmasq»). Для такого устройства работает только подсеть: `@subnets`
перехватывает пакет по адресу назначения.

Но перехват ещё не туннель. Sniffing заменяет адрес именем из SNI, и решение
принимается по имени. Если имени нет в списке доменов, правило по подсетям
(`IPIfNonMatch`) сверяет адрес, который движок сам получит для этого имени
через свой резолвер, а не тот, к которому шёл клиент. Другой узел CDN — и
соединение уходит `direct`. Поэтому сервис заводят и доменом (для решения
движка), и подсетью (для клиента с чужим DNS). Проверка: `grep ИМЯ
/var/run/byway/access.log` показывает `-> proxy`; журнал пишется при `show_usage
1` (кроме `list_mode all`) или `log_level` `info`/`debug`.

## Собственный трафик роутера

`prerouting` не видит пакеты самого роутера, они идут через `output`. А
резолвер роутера тоже смотрит на DNS-вход и для имени из списка отдаёт адрес
из пула. Без отдельной меры роутер не достаёт ни до одного домена из списка.
Мер две.

Первая — прокси-вход `local-in` на `127.0.0.1:1603` (`local_proxy_port`),
HTTP-прокси Xray-core. Работает без правил в ядре. Через него byway делает
свои загрузки (`net_get`): проверка версии, `byway update`, `byway engine`,
готовые списки, словарь при `byway lang en`. При неудаче — напрямую, затем
напрямую с `curl --resolve` на адреса GitHub из DoH (`gh_resolve`, `doh_a`:
запрос к `https://8.8.8.8`, затем `https://1.1.1.1` по адресу, не по имени).
Третья попытка нужна, когда туннель сломан, а GitHub в списке: резолвер
роутера отдаёт для него подставной адрес. Подписка — без третьей попытки.
`byway health` ходит только через этот вход и напрямую не повторяет: он
проверяет именно туннель. Вручную: `https_proxy=http://127.0.0.1:1603 curl …`.

Вторая — заворот `router_via_vpn 1` (включён по умолчанию), для программ,
которые о прокси не знают:

```
chain output {
    type nat hook output priority -100; policy accept;
    meta mark 0x400000 return
    ip daddr @fakeip meta l4proto tcp counter redirect to :1604
}
```

Порт 1604 (`redirect_port`) слушает вход `redir-in` (`dokodemo-door`,
`followRedirect`, sniffing). Заворачивается только TCP и только пул. Подсети
не входят: в подсеть легко попадает диапазон собственного хостера, и
соединение движка к серверу завернулось бы в сам движок. Приоритет записан
числом: nftables 1.0.2 (OpenWrt 22.03) не разбирает здесь имя `dstnat`.

Заворот требует метки `self_mark` (0x400000). Движок работает на том же хосте,
и его исходящие тоже проходят `output`. Не восстановив имя по подставному
адресу, он выпускает пакет `direct` на тот же адрес, а цепочка заворачивает
его обратно. Петля без ограничителя за минуты выедает предел открытых файлов,
и Xray-core перестаёт принимать что-либо, включая перехват всего дома. Адресом
или портом её не исключить — они те же. Поэтому при `router_via_vpn 1` на все
исходящие (`proxy`, `route-*`, `direct`, `dns-out`) ставится `sockopt.mark`, а
первое правило цепочки помеченное пропускает. Ключу в виде готового JSON метку
не подставить — `sockopt.mark` дописывается в него вручную.

**Бит `self_mark` обязан отличаться от бита `mark`.** `ip rule` ловит любую
метку с поднятым битом `mark`; при совпадении пакеты движка к серверу ушли бы
в таблицу 100. Функция `self_mark` при пересечении берёт `0x400000` или
`0x800000` и предупреждает. Если `redirect_port` совпал с `tproxy_port` или
`local_proxy_port`, заворот не ставится вовсе, и byway об этом говорит.

## IPv6

`ipv6 0` — умолчание. Встроенный DNS работает с `queryStrategy: UseIPv4` и
AAAA не отдаёт. Мимо туннеля по IPv6 уходит то, что узнало адрес не у роутера,
и всё, что держится на подсетях: они при выключенной опции только IPv4. При
маршруте IPv6 по умолчанию на роутере `byway doctor` об этом предупреждает.

`ipv6 1` — экспериментально:

- в таблице `inet byway` появляются наборы `fakeip6` (`fakeip6_pool`,
  `fc00::/18` — встроенная константа Xray-core), `privnets6` (`::1`, `::`,
  `::ffff:0:0/96`, `fe80::/10`, `ff00::/8`, `fc00::/7`) и `subnets6` (строки
  IPv6 из того же `subnets.lst`);
- в `prerouting` правило `@fakeip6` стоит выше `@privnets6`, потому что пул
  лежит внутри `fc00::/7`; затем отсечки по `fib` — адреса самого роутера и
  то, что маршрутизируется обратно в мосты (глобальный префикс выдаёт
  провайдер, в набор его не записать);
- в `lists` перехватываются `@fakeip6` и `@subnets6`, в `all` — весь IPv6;
- `ip -6 rule` на ту же таблицу 100 и `local ::/0 dev lo table 100`;
- Xray-core: второй пул fakedns, `queryStrategy: UseIP`, `tproxy-in` и
  `redir-in` слушают `::`, в правило `block` добавлены `::1/128`, `fe80::/10`
  и пул v6;
- в цепочке `output` — заворот `@fakeip6`, в запрете при отказе — набор
  `blocked6`.

## Отказ QUIC

`block_quic 1` (по умолчанию). Ключи поверх TCP (vless, trojan, vmess и
другие) везут UDP клиента внутри TCP, и QUIC там зависает молча: приложение
ждёт десятки секунд и только потом переходит на TCP. Немедленный отказ
переводит его на HTTP/2 сразу. Правило в цепочке `input`:

```
meta mark & 0x100000 == 0x100000 udp dport 443 \
    @th,64,8 & 0xc0 == 0xc0 @th,72,32 { 0x00000001, 0x6b3343cf } counter reject
```

В `input`, потому что `reject` в prerouting ядро не принимает, а tproxy
приводит перехваченный пакет именно сюда, с портом 443. По метке, а не по
адресу: одно правило покрывает пул, подсети, режим `all` и IPv6, а
неперехваченный трафик не трогает. Только первый пакет QUIC — длинный
заголовок и версия v1 или v2; OpenVPN и WireGuard на udp/443, DTLS, STUN и
пакеты уже идущих сессий проходят. В режиме `all` перехвачено всё, и QUIC к
`.ru` при `ru_direct` тоже отклоняется. С ключами hysteria2, wireguard и kcp
туннель сам по UDP, опцию можно выключить. `block_quic` живёт только в
правилах nft и потому входит в `nft_sig` (см. reload).

## Если движок не поднялся

`byway plumb on` сначала проверяет движок и только потом что-то меняет:
`nslookup` первого имени списка на `dns_listen` должен вернуть адрес из пула
(при пустом списке — любой ответ). Попыток 15 с паузой в секунду, но
`nslookup` в каждой может висеть сам, и ожидание бывает дольше 15 секунд; если
процесса Xray-core нет пять проверок подряд, сдаётся раньше. Проба не прошла —
правила не ставятся, dnsmasq возвращается провайдеру (`dns_down`), вызывается
`block_on`. Та же ветка срабатывает, когда ядро отвергло правила (`nft -c`)
или не уложило их (`nft -f`); при отказе укладки снимаются ещё маршрут в
таблице 100 и прежняя таблица `inet byway`. Дальше решает `on_failure`.

`open`: `block_on` ничего не делает. Дом с интернетом и без
туннеля. **Список не перестаёт работать — он работает мимо VPN:** имена
разрешаются в настоящие адреса, соединения идут с домашнего адреса, и снаружи
всё выглядит исправным.

`closed` — «не пускать мимо VPN», умолчание (в поставке и в коде: всё,
кроме `open`, считается `closed`; на установках, где в конфиге записано
`open`, оно и остаётся). Что закрывается, решает `list_mode`:

| режим | что ставит `block_on` |
|---|---|
| `lists` | `byway-block.conf` в `conf-dir` dnsmasq: `address=/ИМЯ/` для простых имён списка — NXDOMAIN на запрос любого типа, A, AAAA и HTTPS (после `dnsmasq --test`); таблица `inet byway_block`, цепочка `forward`: с перечисленных мостов на `@blocked` / `@blocked6` (подсети) — `reject` |
| `all` | таблица `inet byway_block`, цепочка `forward`: с перечисленных мостов всё, кроме трафика между ними и в `privnets`, — `reject` |

Запрет висит на `forward`. Собственный трафик роутера не закрыт — движок может
достучаться до сервера и подняться; LuCI и ssh идут через `input` и не задеты;
мосты вне `list interface` не закрыты. `keyword:` и `regexp:` по имени не
закрыть (dnsmasq сопоставляет суффиксом) — byway называет их число. Итог
пишется в `/tmp/byway-blocked`: `lists`, `all` или `none` (закрывать нечего
либо ядро не приняло правило), рядом в `/tmp/byway-blocked.sig` — md5 от
режима, мостов, IPv6 и объединённых списков. Повторный `block_on` с той же
подписью ничего не делает; с другой пересобирает запрет на месте, без снятия:
таблица заменяется одной транзакцией (прелюдия `table`/`delete table`), файл
dnsmasq — после `dnsmasq --test` и только если он изменился. В режиме `all`
файл имён снимается.

При `closed` служба зовёт `byway plumb close` ещё до запуска движка: после
перезагрузки dnsmasq встаёт с резолверами провайдера раньше byway, и в окно
ожидания список утекал бы напрямую.

Остановка, за которой следует старт (restart, reload с новым конфигом,
обновление, `BYWAY_KEEP_DNS`), и замена ядра (`BYWAY_KEEP_BLOCK` от
`byway engine`, в том числе через память) при `closed` сперва зовут
`plumb close`, а перехват снимают с `--keep-block`: окна, когда подсети списка
идут напрямую, нет.

Снимают запрет успешный `plumb on`, `byway plumb off` и настоящая остановка
службы. На отказе служба и `byway watch` зовут `plumb off --keep-block`, и
запрет остаётся.

Пин в `/etc/hosts` перебивает fakedns: dnsmasq отвечает по нему сам, имя не
идёт в туннель и не закрывается запретом. `byway doctor` такие пины считает.

## Сборка конфига

`byway gen` (`cmd_gen`) собирает `/etc/byway/config.json` из UCI и списков:

1. Замок `/var/run/byway-gen.lock`.
2. Объединение списков: свой файл, готовые списки, направления. Кэш —
   `/tmp/byway-domains-all.lst` и `/tmp/byway-subnets-all.lst`,
   пересобирается, если сменился набор источников или файл новее кэша.
3. Каждое значение UCI, идущее в JSON или в правила nft, сверяется с образцом
   (`val_or`); не подошло — умолчание и предупреждение. Значения приходят и из
   панели, и из чужой выгрузки (`byway import`), поэтому проверяются.
4. Черновик `/tmp/byway-config.new.json` (права 600) проверяется `xray run
   -test -c`. Отвергнут — черновик остаётся, печатаются ошибка и подсказка,
   рабочий конфиг не тронут, код возврата 1. Принят — предупреждения движка об
   устаревших полях выводятся.
5. Строки списков, не похожие ни на имя, ни на подсеть, отбрасываются
   (`/tmp/byway-bad-entries`); у принятого конфига число и первые три
   печатаются до сравнения с рабочим, то есть и тогда, когда конфиг не
   изменился.
6. Совпал с рабочим (`cmp`) — ничего не меняется. Иначе проверка свободного
   места и `mv` поверх рабочего, права 600.

Служба вызывает `byway gen` при каждом старте. Не собралось, а прежний конфиг
проходит `xray run -test`, — движок поднимается на прежнем.

Память. Init-скрипт передаёт движку `GOMEMLIMIT` через `procd_set_param env`
(функция `xray_memlimit`): опция `xray_memlimit` не задана — 40 % от
`MemTotal`, не меньше 32 МиБ; `0`/`off`/`no` — не задаётся; форма Go (`B`,
`KiB`, `MiB`, `GiB`, `TiB`) — как есть; `MB`/`M` → `MiB`, `GB`/`G` → `GiB`;
голое число — мегабайты (`96` → `96MiB`); прочее — строка в системном журнале
`предел памяти «…» не разобран -- взят авто` и 40 %. Без перевода Go не
принял бы `128MB`, движок падал бы при старте, и procd поднимал бы его по
кругу. Без предела Go даёт куче вырасти вдвое против живых
данных, и на роутере с небольшой памятью ядро убивает движок по OOM. Предел
мягкий: живые данные не режет, Go лишь чаще собирает мусор. Пустую опцию uci
выбрасывает, поэтому умолчание живёт в коде. Действующее значение показывает
`byway status`.

Путь к движку — `xray_bin`. Принимается, только если лежит в `/usr/bin`,
`/usr/sbin`, `/usr/local/bin`, `/bin` или `/sbin`, не содержит `..`, имя файла
начинается с `xray`, файл исполняем, начинается с заголовка ELF и `version`
начинается с `Xray `. Имя и ELF проверяются до запуска: `xray_bin=/sbin/reboot`
иначе перезагружал бы роутер на каждом вызове byway. Симлинк с именем `xray*`
в одном из этих каталогов проходит, куда бы он ни указывал. Иначе и скрипт, и
init-скрипт берут `xray` из `PATH`, затем `/usr/bin/xray`.

## Служба procd

`START=21` — сразу за сетью (20), dnsmasq и firewall (19); `STOP=10`. При
прежнем `START=90` от подъёма dnsmasq до запрета при `closed` проходили
десятки секунд, и клиенты успевали получить настоящие адреса и держали их до
TTL. Установщик зовёт `disable` перед `enable`, чтобы снять старую
`S90byway`, и убирает её из `/etc/sysupgrade.conf`. Инстанс:
`$XRAY run -c /etc/byway/config.json`,
`stdout` и `stderr` в системный журнал (Xray-core пишет в stdout), pidfile
`/var/run/byway.pid`, `respawn 3600 5 0`. Движок идёт от системного
пользователя `byway` в клетке `procd-ujail` (`procd_add_jail byway`, права из
`/var/run/byway-caps.json`: `CAP_NET_RAW` либо `CAP_NET_ADMIN` на ядре до 5.17,
плюс `CAP_NET_BIND_SERVICE`, `no_new_privs`); в pid-файле — обёртка, движок её
потомок. Конфиг читается группой (`640 root:byway`), журнал обращений лежит в
`/var/run/byway/` (root 755). Нет `/sbin/ujail` либо `xray_root 1` — движок от
root. Смена `xray_root` и ядра замечается `reload`: он сверяет, от кого идёт
процесс, и перезапускает.

Параметры: порог 3600 с, пауза перед перезапуском 5 с, попыток 0 — без
предела. Порог у procd означает не «столько падений за час»: счётчик
сбрасывается только после работы дольше порога. С конечным числом попыток
несколько падений, разнесённых хоть по полчаса, останавливают службу навсегда,
причём `stop_service` не вызывается — dnsmasq остался бы смотреть в порт,
который никто не слушает.

`start`: `enabled` не `1` — `byway plumb off --service` и выход. При `closed`
— `byway plumb close`. Нет файла движка — подсказка и выход; лежит рядом
запускаемый `/usr/local/bin/xray-*` — подсказка называет его, иначе служба
ставит метку `/tmp/byway-engine-restore` и через 15 с в фоне зовёт `byway
engine restore` (вывод — в системный журнал), один раз за загрузку. Затем
`byway gen`, инстанс procd, и в `service_started` до трёх попыток `byway plumb
on` с паузой 10 с — в фоне, потому что вместе с ожиданием это до минуты, а
панель обрывает запрос через ~20 секунд. PID цикла —
`/var/run/byway-plumb.pid`. Слепок применённого — `/var/run/byway.applied`:
md5 `config.json` и md5 вывода `byway nftsig`.

Правила перехвата ставятся после движка, не раньше: `dns_up` уводит весь
резолв роутера на DNS-вход, и при мёртвом движке дом остался бы без DNS.

`stop`: сначала убивается фоновый цикл и его дети (если PID ещё принадлежит
byway), затем `byway plumb off --service`. Флаг `--service` не ставит отметку
«сняли руками» (`/tmp/byway-plumb-down`), иначе `byway watch` не восстановил
бы правила после неудачного старта.

`restart` и ветка reload «конфиг изменился» передают `--keep-dns`: резолвер
остаётся на DNS-входе, сбрасывается только кэш. Возврат к провайдеру и обратно
дал бы два окна без DNS. Не ответит движок — `plumb on` вернёт dnsmasq
провайдеру на ветке отказа. При `closed` перед снятием перехвата ставится
запрет и остаётся до удачного `plumb on` (см. [Если движок не
поднялся](#если-движок-не-поднялся)).

`reload`. `service_triggers` регистрирует `procd_add_reload_trigger byway`, и
procd зовёт reload по `reload_config`, то есть на каждое «Сохранить и
применить» в LuCI, включая смену языка панели; сам byway зовёт его после
обновления готовых списков. Голый `uci commit byway` из консоли службу не
трогает — после него нужен `/etc/init.d/byway reload`. Reload зовут часто,
поэтому `reload_service` перезапускает только то, что изменилось:

1. `enabled 1`, движок не работает — `start`; `enabled 0`, работает — `stop`.
2. Движок запущен не из того файла, на который сейчас указывает путь к движку
   (сверка `/proc/PID/exe`), или с другим пределом памяти (`GOMEMLIMIT` в
   `/proc/PID/environ` против `xray_memlimit`), — `stop` + `start` с
   `--keep-dns`.
3. `byway gen`. Не собрался — работает прежний.
4. md5 `config.json` ≠ первая строка слепка — `stop` + `start` с `--keep-dns`.
5. md5 `byway nftsig` ≠ вторая строка — только `byway plumb on`, движок не
   трогается.
6. Иначе ничего.

`nft_sig` — подпись правил без их сборки: `fakeip_pool`, `mark`,
`tproxy_port`, `interface`, `list_mode`, `block_quic` и md5 `subnets.lst` и
`.sub` готовых списков. Остальное меняет `config.json` и ловится шагом 4.
**Новая опция, которая живёт только в правилах nft, должна попасть в
`nft_sig`**, иначе reload её не заметит.

## Периодические задачи

`install.sh` заводит в crontab:

```
*/5 * * * * /usr/local/bin/byway watch >/dev/null 2>&1
7 * * * *   /usr/local/bin/byway stat  >/dev/null 2>&1
* * * * *   /usr/local/bin/byway pulse >/dev/null 2>&1
```

`byway pulse` делает одно: смотрит, жив ли движок, и зовёт те же `engine_gone`
и `engine_back`, что и `watch`. Он молчит в минуты, кратные пяти, — тогда
работает `watch`. Падение и возвращение движка поэтому замечаются за одну-две
минуты, а не за пять.

Обновление списков и проверка версии своих задач не имеют — их делает `byway
watch`.

### byway watch

Раз в 5 минут снимает состояние (PID движка, таблица nft, `ip rule`, маршрут,
куда смотрит dnsmasq, отдаёт ли резолвер подставной адрес) и по порядку:

1. При `enabled 1` файл движка не проходит `xray_ok`, запускаемого
   `/usr/local/bin/xray-*` рядом нет, а метке `/tmp/byway-engine-restore`
   больше 15 минут или её нет — метка обновляется, в фоне `byway engine
   restore`, вывод в системный журнал. Флешу нужно 25 МБ свободных; меньше —
   отказ до загрузки.
2. Движка нет при `enabled 1` и без отметки «сняли руками» — `block_on`
   (действует при `closed`). Промахи считаются в `/tmp/byway-nopid`. На втором
   подряд, если dnsmasq смотрит на DNS-вход, — `plumb off --service
   --keep-block`: резолвер к провайдеру, запрет остаётся. В журнал —
   `(nodns)`.
3. Движок вернулся, запрет стоит — `plumb on` независимо от `guard`: удачный
   снимает запрет (`(healed)`), неудачный его оставляет (`(failed)`). При
   `enabled` не `1` — просто `block_off`.
4. Движок есть, `enabled 1`, `guard` не `0`, нет отметки «сняли руками»
   (`/tmp/byway-plumb-down`), а таблицы, правила, маршрута или своего адреса
   в `dhcp.@dnsmasq[0].server` нет — `plumb on`, в журнал `(healed)` или
   `(failed)`. Адрес сверяется по UCI, а не по работающему dnsmasq. Так
   чинится чужой `nft flush ruleset` или перезагрузка firewall.
5. Готовые списки, проверка версии, автообновление (ниже), раз в час —
   `watch_hosts`: при `dns_route tunnel` адреса серверов из `dns.hosts`
   сверяются с DNS; сменился адрес (прежнего нет среди ответов) — `byway gen`
   и `reload` (метка `/tmp/byway-hostcheck`).
6. `/var/run/byway/access.log` больше 4 МБ — обрезается до нуля: значит, не
   работает `byway stat`.
7. Строка состояния дописывается в `/etc/byway/health.log` (200 строк), только
   если что-то изменилось или чинилось. Сменился PID движка, а резолвер уже
   отдаёт адрес из пула — `killall -HUP dnsmasq`.

`byway plumb off` без `--service` ставит `/tmp/byway-plumb-down`, и `byway
watch` не трогает правила до следующего `plumb on` или перезагрузки.

### byway stat

cron зовёт `byway stat` раз в час, в :07, при любых настройках. Карту адресов
(ниже) он достраивает всегда, а считать есть что, только если журнал
обращений пишется (`show_usage 1` при `list_mode lists` или `log_level`
`info`/`debug`; иначе в конфиге `"access": "none"`). В режиме `all` сбор
выключен и при `show_usage 1`: журнал писал бы адрес каждого соединения
дома.

Строка журнала пишется при приёме соединения, до sniffing, и содержит адрес из
пула, а не имя. Поэтому `byway stat` строит обратную таблицу «адрес → имя»
(`/var/run/byway/fakemap`), спрашивая DNS-вход про имена списка — не больше 200 за
запуск, место остановки в `.pos`. Таблица привязана к PID движка. Из журнала
берутся строки `tproxy-in -> proxy` и `-> route-ИМЯ` новее отсечки
(`/var/run/byway/statmark`), счётчики складываются в `/etc/byway/usage.tsv`;
адреса без имени (подсети) — строкой `(по IP)`. В учёт не попадает только
трафик самого роутера. Во флеш файл пишется только при изменении. Журнал
обрезается до 50 строк записью поверх, не `mv`: движок держит файл открытым с
`O_APPEND`, и подменённый файл увёл бы запись в удалённый. Смотреть: `byway
top [N]`.

### Готовые списки по расписанию

`lists_update`: `90m`, `12h`, `2h37m`, `1d`; голое число — минуты; пусто или
`0` — не обновлять; меньше 30 минут не бывает. Нужен хотя бы один `preset`.
Время прошлой попытки — mtime `/etc/byway/presets`: он обновляется до
загрузки, поэтому и неудачная попытка откладывает следующую на полный срок.
Срок вышел — `byway presets`, ошибки в системный журнал, `/etc/init.d/byway
reload`. Срабатывает на ближайшем `byway watch` после истечения срока.

### Проверка версии и автообновление

`update_check 1` (умолчание) — раз в случайные 12–36 часов запрос к GitHub
API `releases/latest`. В `/tmp/byway-upcheck` лежит промежуток до следующей
проверки в минутах (720–2160, случайность из `/proc/sys/kernel/random/uuid`),
mtime файла — время прошлой. Новее — номер в `/tmp/byway-newver`, первая
строка описания в `/tmp/byway-relnote`, момент первого появления в
`/etc/byway/.newver-seen`, строка в журнал. Ничего не скачивается.

`auto_update 1` ставит найденное само; без `update_check` ставить нечего.
Нужны все условия:

- часы синхронизированы (год не меньше 2020);
- местный час роутера равен `auto_update_hour` (`04`; у прошивки из коробки
  пояс UTC, итоговый час называет `byway doctor`);
- та же минорная ветка (`X.Y` совпадает);
- с первого появления прошло трое суток — если описание не начинается с
  `ВАЖНО`, `CRITICAL` или `!`;
- md5 `/usr/local/bin/byway` равен `/etc/byway/.binmd5` от установщика —
  правленный руками файл не обновляется, а без `.binmd5` обновление не
  ставится вовсе;
- версия не откатывалась раньше (`/etc/byway/.au-failed`), попытки не было
  последние сутки (`/etc/byway/.au-try`).

Порядок: копия прежней версии целиком в `/etc/byway/prev.tgz` (не вышло —
отмена), `byway update` (архив тега с GitHub, проверка подписи и его
`install.sh`), затем до 150 секунд проверка
`alive_ok`: процесс движка, таблица `inet byway`, подставной адрес от
резолвера (при пустом списке он не проверяется). Если до обновления проходил
`tunnel_ok` — запрос `curl` через прокси-вход (`local_proxy_port`, 1603) к
`example.com`, годится любой ответ HTTP, — он должен пройти и после. Не
поднялось — `prev.tgz` распаковывается на место (`byway update --rollback`
делает то же), служба перезапускается, версия пишется в `.au-failed`. **Откат
возвращает версию целиком:** программу, init-скрипт, панель и словари. Итог — `/tmp/byway-autoupdate` и
системный журнал.

### Замена движка

`byway engine ВЕРСИЯ|tested|newest|stable|restore`; без аргумента — что
стоит и что есть. `tested` — константа `XRAY_TESTED` (та же в `install.sh`),
`restore` — номер из имени файла в `xray_bin` (`/usr/local/bin/xray-ВЕРСИЯ`),
иначе `XRAY_TESTED`; при живом ядре `restore` ничего не делает. Архив и
`.dgst` с выпусков XTLS, SHA2-256 сверяется. На MIPS без FPU сборки с GitHub
не запускаются — там движок обновляется пакетом OpenWrt. Меньше 40 МБ
`MemAvailable` — замена не начинается.

На флеше свободно не меньше размера несжатого ядра плюс 5 МБ — новое ядро
кладётся рядом (`/usr/local/bin/xray-ВЕРСИЯ`), проверяется `byway gen`,
прописывается в `xray_bin`, служба перезапускается. После удачи прежнее
`/usr/local/bin/xray-*` удаляется, пакетный `/usr/bin/xray` остаётся. Места
меньше — замена через память, и только если прежнее ядро лежит в
`/usr/local/bin/xray-*`; с пакетным byway отказывает. Сперва скачивается архив
прежней версии для отката, затем служба останавливается примерно на минуту, и
на это время ставится `/tmp/byway-plumb-down`, чтобы `byway watch` не
вмешивался; остановка идёт с `BYWAY_KEEP_BLOCK=1`, и запрет при `closed`
держится всю минуту. В обоих случаях итог проверяется `alive_ok` и, если
связь через сервер была до замены, `tunnel_ok`; при неудаче прежнее ядро
возвращается. При выключенной службе или без ключа проверка туннеля и сверка конфига
пропускаются, на пути «рядом» — и перезапуск службы; без ключа ядро меняется
и через память. Замок —
`/var/run/byway-engine.lock`.

Прежнего ядра нет (не найдено или не запускается) — `eng_fresh`: 25 МБ свободных на флеше
(как у установщика), распаковка в `/usr/local/bin/xray-ВЕРСИЯ`,
проверка запуском, `xray_bin`, перезапуск службы при `enabled 1`. Ни архива
для отката, ни ожидания туннеля: откатываться не на что.

### Фоновые задачи панели

Запрос панели живёт секунды, обновление и замена ядра — минуты, поэтому кнопки
«Поставить обновление» и «Поставить проверенное ядро» зовут `byway job update`
и `byway job engine tested`. `job` отцепляет `byway job run …` (через
`setsid`, если он есть), пишет PID в `/var/run/byway-job.pid` и сразу
отвечает. `job run` пишет вывод прямо в `/tmp/byway-job.log`, без конвейера,
чтобы ход был виден по мере работы, и в конце строку `== конец`. Одна задача
за раз: при живом PID — отказ. `byway job log` отдаёт журнал без цветов и,
пока задача жива, строку `… идёт` с кодом 3; панель опрашивает его раз в 3 с.
`byway doctor` и `byway report` панель зовёт напрямую — они укладываются в
секунды.

## dnsmasq

`dns_up` работает с `dhcp.@dnsmasq[0]`:

1. Снимка нет — прежнее состояние пишется в `/etc/byway/dns-saved`:
   `noresolv=`, строки `server=` (кроме своего адреса), `listen=` — свой адрес
   на момент подъёма.
2. Из `server` удаляются общие резолверы. Записи `/домен/адрес` остаются: это
   раздельный резолв для своей сети.
3. `server` += `127.0.0.42`, `noresolv=1`. Без `noresolv` dnsmasq спрашивал бы
   и провайдера, брал первый ответ, и часть имён списка получала бы настоящий
   адрес.
   Туда же `server=/use-application-dns.net/`, если её нет: запись без адреса
   значит «только локально», и dnsmasq отвечает NXDOMAIN. Это канарейка
   Firefox: DoH, включённый им самим (в России по умолчанию с 2022 года), он
   по этому ответу выключает и спрашивает роутер. DoH, включённый вручную,
   «Частный DNS» Android и профили DNS iOS канарейку не слушают.
4. dnsmasq уже смотрит на DNS-вход и канарейка уже стояла — HUP, иначе
   `restart`: новую строку `server` dnsmasq читает только при перезапуске.

**Правка `dhcp` не коммитится.** Она живёт дельтой в `/tmp/.uci`:
`/etc/init.d/dnsmasq` её видит, а перезагрузка стирает вместе с tmpfs.
Закоммиченная, она пережила бы потерю питания, sysupgrade и остановку движка,
и дом остался бы с резолвером, указывающим в пустоту. Сейчас худший исход —
роутер встаёт с DNS провайдера и без туннеля. Оговорка: «Сохранить» на
странице DHCP в LuCI коммитит все висящие правки, включая эту.

`dns_down`: `uci revert dhcp` (снимает и чужие некоммиченные правки `dhcp`,
если были); если свой адрес всё же в сохранённой конфигурации, резолверы
восстанавливаются из `dns-saved` явно, с записями `/домен/адрес` (кроме
канарейки), и `uci commit dhcp`; `dns-saved` удаляется; dnsmasq перезапускается, если ещё смотрит
на DNS-вход или его состояние не определить, иначе HUP. Поэтому `byway plumb
off` возвращает резолвер провайдеру и тогда, когда правку закоммитил кто-то
другой.

## Замки

Замок — каталог (`mkdir` атомарен) с файлами `pid` и `byway`. Без файла
`byway` — чужой, снимается сразу. С мёртвым PID — остаток прерванного запуска,
снимается. С живым — ожидание до 30 секунд.

| замок | кто берёт | если занят |
|---|---|---|
| `/var/run/byway-gen.lock` | `byway gen` | выход с ошибкой |
| `/var/run/byway-plumb.lock` | `byway plumb on/off/close` | `return 1`: `byway watch` продолжает работу |
| `/var/run/byway-engine.lock` | `byway engine` | выход с ошибкой |

Замки в `/var/run`, а не в `/tmp`: на OpenWrt это `/tmp/run` с владельцем root
и правами 755. В `/tmp` (1777) каталог замка мог бы создать любой процесс,
включая dnsmasq под своим пользователем, и запереть сборку и правила
перехвата.

## Файлы

| путь | что |
|---|---|
| `/usr/local/bin/byway` | скрипт; симлинк `/usr/bin/byway` — `/usr/local/bin` в `PATH` OpenWrt не входит |
| `/usr/local/bin/byway-uninstall` | удаление (симлинк `/usr/bin/byway-uninstall`) |
| `/usr/local/bin/xray-ВЕРСИЯ` | движок, если ставился с GitHub |
| `/etc/init.d/byway` | служба |
| `/etc/config/byway` | UCI: секция `main`, секции `route` для направлений |
| `/etc/byway/domains.lst`, `subnets.lst` | свои списки; домены понимают `full:`, `keyword:`, `regexp:` |
| `/etc/byway/presets/ИМЯ.lst`, `ИМЯ.sub` | скачанные готовые списки: домены и подсети |
| `/etc/byway/routes/ИМЯ.lst` | список направления |
| `/etc/byway/config.json` | собранный конфиг Xray-core, права 640 root:byway (600 при Xray от root) |
| `/etc/byway/lang/en.tsv` | словарь «ключ⇥перевод», только при английском |
| `/etc/byway/dns-saved` | что было у dnsmasq, пока правила стоят |
| `/etc/byway/health.log`, `usage.tsv` | журнал `byway watch`, учёт `byway stat` |
| `/etc/byway/prev.tgz`, `.binmd5`, `.au-try`, `.au-failed`, `.newver-seen` | автообновление; `prev.tgz` — прежняя версия целиком для отката |
| `/var/run/byway/access.log` | журнал обращений Xray-core |
| `/tmp/byway-config.new.json` | черновик; остаётся, если движок его отверг |
| `/tmp/byway-domains-all.lst`, `byway-subnets-all.lst` (+ `.sig`) | объединённые списки |
| `/tmp/byway-bad-entries` | отброшенные строки списков |
| `/tmp/byway-blocked`, `.sig` | действующий запрет: `lists`, `all`, `none`; подпись, по которой он пересобирается |
| `/tmp/byway-plumb-down` | правила сняты вручную |
| `/tmp/byway-route-mine`, `byway-route-mine6` | маршрут в таблице 100 создан byway |
| `/tmp/byway-watch.last`, `byway-nopid` | прошлое состояние и счётчик промахов `byway watch` |
| `/var/run/byway/fakemap`, `fakemap.pos`, `statmark` | учёт `byway stat` |
| `/tmp/byway-upcheck`, `-newver`, `-relnote`, `-autoupdate` | проверка версии, итог автообновления |
| `/tmp/byway-engine-restore` | метка попытки поставить пропавшее ядро: служба — раз за загрузку, `byway watch` — когда она старше 15 минут |
| `/tmp/byway-job.log`, `/var/run/byway-job.pid` | ход и PID фоновой задачи панели (`byway job`) |
| `/var/run/byway.pid`, `byway.applied` | PID обёртки ujail (движок — её потомок); слепок применённого для reload |
| `/var/run/byway-caps.json` | права движка для procd-ujail |
| `/tmp/byway-hostcheck` | метка часовой сверки адресов серверов (`watch_hosts`) |
| `/var/run/byway-plumb.pid`, `byway-nostart` | фоновый цикл подъёма; «старт отказал, цикл не запускать» |
| `<conf-dir dnsmasq>/byway-block.conf` | запрет по именам при `closed` |
| `/www/luci-static/resources/view/byway/`, `.../resources/byway/` | панель; в `ui.js` установщик вписывает номер версии (`BUILT`), и при расхождении с `byway version` панель предупреждает, что браузер показывает её из кэша |
| `/usr/share/luci/menu.d/`, `/usr/share/rpcd/acl.d/luci-app-byway.json` | меню и права панели |

Всё в `/tmp` и `/var/run` живёт в памяти и исчезает при перезагрузке.
`install.sh` вносит в `/etc/sysupgrade.conf` каталог `/etc/byway/`,
init-скрипт, ссылки `/etc/rc.d/S21byway` и `K10byway`, файлы скрипта и файлы
панели. Движок туда не входит (35 МБ): после sysupgrade его ставит сама служба
через `byway engine restore` (см. [Служба procd](#служба-procd)).

## Где смотреть

|---|---|
| что поднято | `byway status` |
